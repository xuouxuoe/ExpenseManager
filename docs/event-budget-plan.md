# งบทริป / งบโครงการ (EVENT budget) — แผน

สถานะ: **อนุมัติ 2026-11-27** (schema ข้อ 3, ไม่นับในงบรายเดือน, บังคับเจ้าของตรงกัน) · E1 push แล้ว (ข้อ 8) · **E2 implement ในเครื่องแล้ว** (ข้อ 9) · E3 ยังไม่เริ่ม

## 1. ความต้องการ (ผู้ใช้ 2026-11-27)

ตั้งงบไว้สำหรับแผนไปเที่ยว แล้วเวลาใช้จ่ายให้ **เลือกว่าใช้เงินจากงบนี้** และดูได้ว่าใช้ไปเท่าไร เหลือเท่าไร

ผู้ใช้เลือกทางเลือก ข. (งบแบบใหม่ในเมนูงบใช้จ่าย) แทนการใช้แผนชำระ เพราะแผนชำระ:
- บังคับหมวดและชื่อรายการเดียวกับแผน
- จ่ายจากบัตรเครดิตไม่ได้
- จ่ายเกินยอดแผนไม่ได้
- บันทึกได้แค่จากหน้าแผนชำระ

## 2. ขอบเขต

| ระยะ | งาน |
|---|---|
| E1 | งบประเภท EVENT (ช่วงวันที่ หลายหมวด) + ช่อง "ใช้จากงบ" ในฟอร์มรายการ + หน้าสรุปงบทริป + กรองรายการตามงบ + CSV/Pivot มี budget_name |
| E2 | LINE / Integration API: ระบุงบตอน `draft.create` (รับ ID หรือชื่อ) และ AI เลือกงบจากข้อความ เช่น "ราเมน 350 งบญี่ปุ่น" |
| E3 (ต้องออกแบบเพิ่ม) | **กันเงินจริง** ให้ "เงินที่ใช้ได้จริง" ลดลงตั้งแต่ก่อนเดินทาง (ใช้กลไก Reservations เดิม) |

E1 ไม่กันเงินจริง: งบเป็นเพดานการใช้จ่ายและตัวติดตามยอด เหมือนงบรายเดือน

## 3. Schema ที่เสนอเพิ่ม (ต่อท้าย header เดิม ไม่ย้ายคอลัมน์เดิม)

```text
Budgets: ... (เดิม 11 คอลัมน์), budget_kind, start_date, end_date
Transactions: ... (เดิม 25 คอลัมน์), budget_id, budget_name
```

| Table | Column | Type | Kind | คำอธิบาย |
|---|---|---|---|---|
| Budgets | budget_kind | Enum | INPUT | `MONTHLY` (งบเดิม; แถวเดิมที่ว่างอ่านเป็น MONTHLY) / `EVENT` |
| Budgets | start_date | Date | INPUT | EVENT: วันเริ่ม (บังคับ); MONTHLY: ว่าง |
| Budgets | end_date | Date | INPUT | EVENT: วันสิ้นสุด ≥ start_date ห่างไม่เกิน 366 วัน (บังคับ); MONTHLY: ว่าง |
| Transactions | budget_id | ID | INPUT | FK → Budgets ที่เป็น EVENT; ว่าง = ไม่ใช้งบทริป |
| Transactions | budget_name | Text | PROJ | ชื่องบจาก Budgets (refresh เมื่อเปลี่ยนชื่องบ) |

- คอลัมน์ใหม่เพิ่มด้วยกลไกเดิม: อ่าน header รุ่นก่อนโดยเติมค่าว่าง แล้วเติม header ที่ขาดตอนเขียนครั้งแรกภายใต้ lock (database-schema.md §3) ไม่แก้ข้อมูลเดิม ไม่ต้อง Migration
- EVENT ตั้ง `budget_month` = YYYYMM ของ start_date (เพื่อกรอง/เรียงตามเดือน) และ `weekly_amount` = 0
- EVENT ไม่ใช้ BudgetCategories: ยอดใช้ไปนับจาก `Transactions.budget_id` ไม่ใช่จากหมวด

## 4. Business rules ที่เสนอ

### 4.1 การสร้าง / แก้ไขงบ EVENT
- ข้อมูล: ชื่อ (เช่น "เที่ยวญี่ปุ่น ธ.ค. 69"), ยอดงบ > 0, ช่วงวันที่, เจ้าของ (ว่าง = ทุกคน), หมายเหตุ
- แก้ชื่อ ยอด ช่วงวันที่ เจ้าของ และหมายเหตุ = แก้แถวเดิม (ไม่ต้องปิดแล้วสร้างใหม่เหมือนงบรายเดือน เพราะไม่มีชุดหมวด)
- แก้ชื่อ → refresh `budget_name` ในทุกธุรกรรมที่อ้างอิง (เป็น projection ไม่เปลี่ยน updated_at) และเขียน audit หนึ่งเหตุการณ์ ตามรูปแบบ RENAME_MASTER; `refreshProjections()` ครอบคลุม budget_name ด้วย
- ปิดงบ (is_active FALSE): เลือกใช้กับรายการใหม่ไม่ได้ รายการเดิมยังอ้างอิงและนับยอดเหมือนเดิม; ห้ามลบงบที่มีรายการอ้างอิง

### 4.2 การเลือก "ใช้จากงบ" ในรายการ
- เลือกได้เฉพาะประเภทที่รับรู้รายจ่ายตาม Ledger: EXPENSE, CREDIT_PURCHASE, INTEREST, FEE และ REFUND (เพื่อคืนยอดให้งบ); ประเภทอื่นต้องว่าง (backend ปฏิเสธ)
- งบต้องเป็น EVENT ที่เปิดใช้งาน; ถ้างบระบุเจ้าของ เจ้าของรายการต้องตรงกัน
- **ไม่บังคับให้วันที่รายการอยู่ในช่วงทริป** เพราะค่าตั๋วหรือที่พักมักจ่ายล่วงหน้า; ช่วงวันที่ใช้แสดงผลและจัดลำดับตัวเลือก (งบที่วันนี้อยู่ในช่วง หรือกำลังจะถึง ขึ้นก่อน)
- ใช้กับทุกบัญชี รวมบัตรเครดิตและเงินสด และทุกหมวด
- กลับรายการ: รายการกลับคัดลอก budget_id จากต้นฉบับ ยอดใช้ไปของงบจึงลดลงเอง
- แก้รายการ: เปลี่ยนหรือเอางบออกได้ (ตรวจเงื่อนไขเดิมซ้ำ)
- ธุรกรรมที่ระบบสร้างจากแผนชำระ (source PLAN) ยังไม่มีช่องงบใน E1

### 4.3 ยอดของงบ EVENT
- ใช้ไป = ผลรวม `Ledger.effectsOf(t).expenseSatang` ของรายการที่ budget_id ตรงกับงบ (สูตรเดียวกับงบรายเดือน ไม่จำกัดเดือน/หมวด) รวมผลของรายการกลับรายการ
- คงเหลือ = งบ − ใช้ไป (ติดลบได้ แสดงเป็น "ใช้เกิน")
- ระหว่างทริป: วันที่เหลือ และใช้ได้วันละ = คงเหลือ ÷ วันที่เหลือ (ไม่ติดลบ); ก่อนเริ่มแสดง "อีก n วัน"; หลังจบแสดงสรุป
- แยกยอดตามหมวด และตามบัญชี/บัตร

### 4.4 ความสัมพันธ์กับงบรายเดือน (ต้องตัดสินใจ)
- **เสนอ:** รายการที่ระบุงบ EVENT **ไม่นับ**ในงบรายเดือน เช่น ค่าอาหารในทริปไม่กินงบ "ค่าอาหารรายวัน" เพื่อไม่ให้นับสองงบ
- ทางเลือก: นับทั้งสองงบ (งบรายเดือนเห็นยอดรวมจริงของหมวดนั้น)
- รายงานรายรับรายจ่าย Dashboard และ Pivot นับตามปกติทุกกรณี เพราะงบไม่ใช่ผลทางบัญชี

## 5. หน้าจอ

- **เมนูงบใช้จ่าย:** ปุ่มสร้างเลือก "งบรายเดือน" หรือ "งบทริป/โครงการ"; ส่วน "งบทริป" แสดงการ์ดของงบที่เปิดอยู่
  - การ์ดแสดงช่วงวันที่ โดนัท % ใช้ไป ใช้ไป/เหลือ ใช้ได้วันละ และยอดแยกตามหมวด
  - ลิงก์ "ดูรายการ" ไปหน้ารายการที่กรองด้วยงบนั้น
  - งบที่จบแล้วอยู่ในส่วนประวัติ
- **ฟอร์มรายการ:** ช่อง "ใช้จากงบ (ไม่บังคับ)" แสดงเมื่อเป็นประเภทรายจ่ายและมีงบ EVENT ที่เปิดอยู่; เลือกแล้วแสดงคำใบ้ "เหลือ x บาท"; ตัวช่วยกรอก (ใช้ประจำ/ล่าสุด) ไม่เติมงบอัตโนมัติ
- **หน้ารายการ:** ตัวกรอง "งบ" และป้ายชื่องบในแถวรายการ
- **ภาพรวม:** การ์ดงบเดิมแสดงงบทริปที่กำลังดำเนินอยู่ด้วย
- รายงาน CSV ธุรกรรมและ Pivot_Transactions มีคอลัมน์ budget_name

## 6. การทดสอบ (เพิ่ม tests/event-budget.test.js และปรับเทสต์เดิม)

- สร้าง EVENT: ช่วงวันที่ผิด, เกิน 366 วัน, ยอด ≤ 0, ไม่มี start/end → ปฏิเสธ; budget_month = เดือนของ start_date
- ผูกรายการ: ประเภทที่ไม่ใช่รายจ่าย, งบปิด, งบ MONTHLY, เจ้าของไม่ตรง, ID ไม่มีอยู่ → ปฏิเสธ; บัตรเครดิต/เงินสด/หลายหมวด → นับครบ
- กลับรายการและ REFUND → ยอดใช้ไปลดลง; แก้รายการเปลี่ยนงบ → ยอดย้ายถูกต้อง
- เปลี่ยนชื่องบ → budget_name ในทุกธุรกรรมเปลี่ยน ID ไม่เปลี่ยน updated_at ไม่เปลี่ยน; refreshProjections idempotent
- งบรายเดือนไม่นับรายการที่มีงบ EVENT (ตามข้อ 4.4) และงบรายเดือนเดิมทำงานเหมือนเดิม
- ชีตรุ่นเก่า (ไม่มีคอลัมน์ใหม่) อ่านได้ และเติม header เมื่อเขียนครั้งแรก
- idempotency / retry ระหว่างเขียนล้มเหลว ไม่สร้างซ้ำ; งบจำนวนการเรียก Sheets ใน tests/performance.test.js ไม่เพิ่มสำหรับหน้ารายการ
- dev preview: เดสก์ท็อปและมือถือ 375px, ฟอร์มบันทึกพร้อมเลือกงบ, การ์ดงบทริป
