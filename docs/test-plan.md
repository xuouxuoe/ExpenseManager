`tests/reliability.test.js` ผ่าน 8/8 กรณี: 6 fault matrices ข้างต้น, สอง execution จำลองใช้ lock เดียวกัน, และกู้ Audit ของ COMMITTED รุ่นเก่าที่ขาดประวัติพร้อมรองรับ Audit ID แบบสุ่มเดิม

ในแต่ละ fixture ทำให้ล้มเหลวเพียงครั้งเดียวที่ setValues ลำดับที่เลือก แบบก่อนเขียนหรือเขียนสำเร็จแล้วไม่ได้รับ reply จากนั้น retry key/payload เดิมอีกสองครั้ง ตรวจยอดบัญชี ยอดแผน/งวด ธุรกรรม Reservations/Allocations ให้ตรงกับเส้นทางที่ไม่ล้มเหลว ตรวจ PK ไม่ซ้ำ OperationJournal หนึ่งรายการเป็น COMMITTED, operation success Audit หนึ่งเหตุการณ์, RENAME_MASTER หนึ่งเหตุการณ์เมื่อเกี่ยวข้อง และไม่มี lock ค้าง

ก่อนแก้โค้ด เทสต์พบ success Audit หายเมื่อเขียน AuditLogs ล้มเหลวหลัง COMMITTED และพบ RENAME_MASTER หายเมื่อกู้คืนหลัง Master เปลี่ยนชื่อสำเร็จแต่ projection ยังไม่ครบ แก้ให้บันทึก Audit ก่อนยืนยันสำเร็จ ตรวจซ้ำตาม operation/event identity และ checkpoint เหตุการณ์ rename ก่อนเขียน Master

`npm test` รอบล่าสุดผ่าน 128/128 ไม่ skip เทสต์ localhost ที่รอบก่อนติด EACCES ผ่านใน environment ที่เชื่อมต่อกลับมาแล้ว ไม่ได้แก้ network/security settings หรือเปลี่ยนเทสต์ให้ผ่านแบบข้ามการตรวจ

ยังไม่ทดสอบโค้ดใหม่บน Apps Script จริง ไม่ได้อัปโหลด runtime หรือ deploy ต้องตรวจ `/dev` ด้วยฐาน TEST หลังได้รับอนุญาต clasp push และ pull กลับมาเทียบก่อน รวมทั้ง concurrency สอง browser sessions, เครือข่ายขาด/กลับมาและคิว IndexedDB, outage ต่อเนื่อง/หลายจุดพร้อมกัน, และการชนกับงานค้างต่างประเภท การจำลอง lock ในเครื่องเป็น synchronous interleaving ไม่ใช่การทดสอบ Google LockService จริง

## การ์ดและตารางแผนที่บันทึกแล้ว (local)

## 7. Non-functional

- การเขียนพร้อมกัน 2 session (LockService)
- Backend ล้มเหลว / timeout → UI แสดง error และ retry ด้วย key เดิม
- ผู้ใช้ไม่มีสิทธิ์ → ปฏิเสธที่ Backend
- มือถือ: ฟอร์มสร้างแผนและรายการใช้งานได้ที่ 375px
- เวลา refresh ชื่อเมื่อข้อมูล 10,000+ แถว ต่ำกว่าขีดจำกัดเวลา Apps Script
