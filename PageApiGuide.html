คู่มือ API

สำหรับนักพัฒนาที่เชื่อมระบบภายนอก เช่น LINE OA, สคริปต์ หรือ AI เข้ากับ Expense Manager

เริ่มต้น คำขอและคำตอบ Actions ตัวอย่างโค้ด รหัสข้อผิดพลาด ID ข้อมูลหลัก ความปลอดภัย

1. เริ่มต้น

  1. สร้าง API key ที่เมนู เชื่อมต่อภายนอก (key แสดงครั้งเดียว เก็บไว้ฝั่งเซิร์ฟเวอร์ของระบบที่เรียก API)
  2. ใช้ URL ของ deployment สำหรับ Integration (gateway) ที่ลงท้ายด้วย /exec — ไม่ใช่ URL ของหน้าเว็บนี้
  3. ส่ง action ping เพื่อตรวจการเชื่อมต่อ ต้องได้ "ok": true

เก็บไว้ในเบราว์เซอร์นี้เท่านั้น ไม่ส่งไปที่ระบบ · ห้ามใส่ API key ในช่องนี้

2. รูปแบบคำขอและคำตอบ

  • ส่ง POST พร้อม body เป็น JSON (Content-Type: application/json) ขนาดไม่เกิน 100,000 ตัวอักษร
  • ส่ง API key ใน body (api_key) — Apps Script อ่าน HTTP header ไม่ได้ จึงใช้ header Authorization ไม่ได้ และห้ามใส่ key ใน URL
  • Apps Script ตอบกลับด้วย redirect (302) ไปที่ script.googleusercontent.com ก่อน: ผู้เรียกต้องตาม redirect ด้วย GET (ค่าปกติของ curl -L, fetch, Postman) ห้ามส่ง POST ซ้ำไปที่ URL ปลายทาง
  • ระบบตอบ HTTP 200 เสมอ แม้เกิดข้อผิดพลาด — ให้ตรวจค่า ok ในคำตอบ
  • เวลาตอบประมาณ 2–3 วินาทีต่อคำขอ และจำกัด 60 คำขอต่อนาทีต่อการเชื่อมต่อ

3. Actions

สิทธิ์ (scope) กำหนดตอนสร้างการเชื่อมต่อ: READ = ดูข้อมูล, WRITE = บันทึกผ่านร่าง

actionสิทธิ์สถานะหน้าที่
ping—ใช้ได้ตรวจ key และการเชื่อมต่อ คืนชื่อการเชื่อมต่อ สิทธิ์ และฐานข้อมูลที่ใช้
masters.listREADใช้ได้บัญชี เจ้าของ หมวดหมู่ที่ใช้งาน (ID + ชื่อ) สำหรับใส่ใน prompt ของ AI
draft.createWRITEใช้ได้สร้างร่างรายการจาก JSON ตรวจข้อมูลและคืนสรุปให้ผู้ใช้ยืนยัน (ยังไม่บันทึก)
draft.confirmWRITEใช้ได้ยืนยันร่างแล้วบันทึกจริง ยืนยันซ้ำได้ผลเดิม ไม่เกิดรายการซ้ำ
draft.cancelWRITEใช้ได้ยกเลิกร่าง
transactions.recentREADเร็ว ๆ นี้รายการล่าสุด (สูงสุด 20 รายการ)
summary.monthREADเร็ว ๆ นี้รายรับ รายจ่าย และสุทธิของเดือน
balancesREADเร็ว ๆ นี้ยอดบัญชี เงินกันไว้ และเงินที่ใช้ได้จริง
budget.remainingREADเร็ว ๆ นี้งบคงเหลือของเดือนและสัปดาห์

ทุกการบันทึกต้องผ่านร่างและการยืนยันของผู้ใช้ ไม่มี action บันทึกตรง

คืนบัญชี หมวดหมู่ และเจ้าของที่ใช้งานอยู่ (ID + ชื่อ) และค่าเริ่มต้นของการเชื่อมต่อ ควร cache ไว้และดึงใหม่เมื่อได้ VALIDATION_NOT_FOUND

บันทึกรายการ: draft.create → ผู้ใช้ยืนยัน → draft.confirm

  1. draft.create ตรวจข้อมูล แปลงชื่อเป็น ID และเก็บร่าง (ยังไม่บันทึก) คืน draft_id, confirm_token และ summary_text ไว้แสดงให้ผู้ใช้ตรวจ
  2. เมื่อผู้ใช้กดยืนยัน ส่ง draft.confirm พร้อม draft_id + confirm_token ระบบจึงบันทึกจริง (แหล่งที่มา AI) — กดซ้ำได้ผลเดิม ไม่เกิดรายการซ้ำ
  3. ถ้าผู้ใช้ไม่ต้องการ ส่ง draft.cancel; ร่างที่ไม่ยืนยันหมดอายุใน 24 ชั่วโมง
  4. ต้องส่ง request_id กับ draft.create และใช้ค่าเดิมเมื่อส่งซ้ำ (จะได้ร่างและ token เดิม); ถ้าการเชื่อมต่อกำหนด LINE userId ต้องส่ง channel_user_id ทุกคำขอบันทึก และยืนยันได้เฉพาะ userId ที่สร้างร่าง

4. ตัวอย่างการเรียก

แทน <API_KEY> ด้วย key ของคุณในเครื่องที่เรียกเท่านั้น

curl

ใช้ -L และห้ามใส่ -X POST (จะทำให้ส่ง POST ซ้ำตอนตาม redirect)

PowerShell

JavaScript (Node.js 18+)

Postman

Method POST → Body: raw / JSON → วาง JSON ตัวอย่าง → Send (Postman ตาม redirect ด้วย GET ให้อัตโนมัติ)

5. รหัสข้อผิดพลาด (code)

codeความหมายวิธีแก้
BAD_REQUESTไม่มี body หรือไม่ใช่ JSON objectตรวจ Content-Type และรูปแบบ JSON (เครื่องหมาย " ปกติ)
PAYLOAD_TOO_LARGEbody เกิน 100,000 ตัวอักษรลดขนาดข้อมูล
UNAUTHORIZEDไม่มี key, key ผิด, ถูกปิดใช้งาน หรือถูกเปลี่ยนแล้วตรวจ key (ช่องว่างที่ติดมา) หรือสร้าง/เปลี่ยน key ใหม่
FORBIDDENผู้สร้างการเชื่อมต่อไม่มีสิทธิ์ใช้ระบบแล้วให้ผู้มีสิทธิ์สร้างการเชื่อมต่อใหม่
UNKNOWN_ACTIONไม่รู้จัก action หรือยังไม่เปิดใช้ตรวจชื่อ action และสถานะในตาราง Actions
FORBIDDEN_SCOPEkey ไม่มีสิทธิ์ READ/WRITE ที่ action ต้องใช้แก้สิทธิ์ของการเชื่อมต่อ
FORBIDDEN_CHANNELไม่ส่งหรือส่ง channel_user_id ที่ไม่ได้รับอนุญาตเพิ่ม LINE userId ในการเชื่อมต่อ หรือส่งค่าที่ถูกต้อง
RATE_LIMITEDเกิน 60 คำขอต่อนาทีรอแล้วส่งใหม่ (ใช้ request_id เดิม)
INVALID_REQUEST_IDไม่ส่งหรือส่ง request_id ผิดรูปแบบกับ action ที่บันทึกส่ง 8–128 ตัว (A-Z a-z 0-9 _ -) และใช้ค่าเดิมเมื่อส่งซ้ำ
IDEMPOTENCY_CONFLICTrequest_id เดิมถูกใช้กับข้อมูลชุดอื่นแล้วใช้ request_id ใหม่สำหรับรายการใหม่
BUSYระบบกำลังบันทึกรายการอื่นรอสักครู่แล้วส่งซ้ำด้วยข้อมูลเดิม
VALIDATION_*ข้อมูลไม่ถูกต้อง เช่น VALIDATION_NOT_FOUND ไม่พบชื่อ, VALIDATION_AMBIGUOUS ชื่อตรงหลายรายการ, VALIDATION_UNKNOWN_FIELD, VALIDATION_RULE บัญชี/หมวดไม่ตรงประเภท, VALIDATION_FK_INACTIVE ข้อมูลหลักถูกปิดดู details.field และ details.candidates แล้วแก้ข้อมูล
DRAFT_NOT_FOUNDไม่พบร่าง หรือเป็นร่างของการเชื่อมต่อ/ผู้ใช้อื่นตรวจ draft_id และ channel_user_id
INVALID_CONFIRM_TOKENconfirm_token ไม่ตรงกับร่างใช้ token ที่ได้จาก draft.create
DRAFT_EXPIREDร่างเกิน 24 ชั่วโมงสร้างร่างใหม่
DRAFT_NOT_PENDINGร่างถูกยืนยัน ยกเลิก หมดอายุ หรือบันทึกไม่ได้แล้ว (details.draft_status)สร้างร่างใหม่ถ้าต้องการบันทึก
INTERNAL_ERRORข้อผิดพลาดภายใน เช่น gateway ไม่ได้รับสิทธิ์ Spreadsheetลองใหม่ ถ้ายังเกิดให้ดู log INTEGRATION_INTERNAL_ERROR ใน Executions ของ gateway

6. ID ข้อมูลหลัก

บัญชี หมวดหมู่ และเจ้าของที่ใช้งานอยู่ ใช้อ้างอิงใน params (ส่ง ID ไม่ต้องส่งชื่อ)

7. ความปลอดภัย

  • เก็บ API key ฝั่งเซิร์ฟเวอร์เท่านั้น ห้ามใส่ในโค้ดหน้าเว็บ แอปมือถือ ห้องแชต หรือ repository
  • เก็บ confirm_token ไว้ฝั่งระบบที่เรียก (เช่นใน postback ของปุ่ม) ไม่แสดงในข้อความแชต
  • ใช้หนึ่งการเชื่อมต่อต่อหนึ่งระบบ เพื่อปิดหรือเปลี่ยน key ได้เฉพาะจุด และกำหนด LINE userId ที่อนุญาตเมื่อใช้กับ LINE
  • ให้สิทธิ์เท่าที่จำเป็น (ระบบที่อ่านอย่างเดียวให้ READ)
  • สงสัยว่า key รั่ว ให้กด "เปลี่ยน key" ทันที key เดิมจะใช้ไม่ได้
  • ข้อความที่ส่งผ่าน LINE และผู้ให้บริการ AI จะผ่านระบบภายนอก ส่งเฉพาะข้อมูลที่จำเป็น
